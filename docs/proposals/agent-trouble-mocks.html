When an agent can't answer

Tonight you asked Everyone in "A joint space" for pi. Jacobian answered; OpenClaw said nothing, and nothing in Chips said why. OpenClaw's machine had stopped at 6:11 PM. Its bridge to Chips was still connected, so Chips believed OpenClaw was fine, and your message sat in the bridge until OpenClaw came back at 6:34.

Chips could know three things, and today it shows none of them:

  1. It hasn't picked this up. A message went to an agent, and nothing has come back from that agent in the room: no run, no "thinking", no words. Chips can see this by itself, for any agent, whatever went wrong.
  2. It's offline. Its connection to Chips has closed. Chips knows this now, in memory, and tells nobody. Tonight it would have said "online", since the bridge stayed connected.
  3. It says it's in trouble. The agent tells Chips what is wrong with the part Chips can't see: the bridge that can't reach OpenClaw, or Jacobian when its model provider fails. This needs a new event in the protocol and a line in each agent.

Each phone below loops the same few seconds in the room from tonight: you send to Everyone, Jacobian thinks and answers, and OpenClaw doesn't.

A · Under your message

Signal 1 only. If an agent the message went to shows nothing within 30 seconds, a quiet line appears under your message with its face: "OpenClaw hasn't picked this up · 30s". The time counts up, and the line goes the moment anything arrives from that agent. It can't say why, but it catches every silent failure, including ones nobody has thought of.
Cost: Chips only, no protocol change. Core ≈120 lines with tests (a message's waiting agents, from its addressed_to and what each has said since); phone ≈60; desktop ≈40.

B · A, and the agent's state recommended

A, plus signals 2 and 3. An agent in trouble wears a small amber mark on its face everywhere it appears: in the room's header, in the field's faces, and in the + list. An offline agent's face is drawn faded in the same places. The header says "1 can't answer". Because Chips already knows, the line under your message appears as soon as you send, and says why: "OpenClaw can't answer yet · can't reach its gateway since 6:12 PM · it'll get this when it's back". A's 30-second watch still covers anything the agent didn't report.
Cost: an ADR and one new event, harness.status (ok / offline / trouble, plus a line saying why). The server records offline when a connection closes and publishes each change; the SDK gets reportTrouble(why) and reportOk(). On top of A: server ≈150 lines, core ≈100, phone ≈120, desktop ≈80. The bridge ≈30 and Jacobian ≈40 report their own trouble.

C · B, with a strip over the field

B, louder. While an agent in this room can't answer, a strip over the field says so before you type: "OpenClaw can't answer right now · Can't reach its gateway · since 6:12 PM". A tap opens the agent's page. The strip goes when the agent is back. Under your message it says only "OpenClaw will get this when it's back".
Cost: B, plus the strip: phone ≈60 lines, desktop ≈40. It takes about 50 points of the room while an agent is down.

The Harnesses tab, in B and C

Each agent's row says its state in words, not only as a dot. An offline agent reads "Offline · since 6:12 PM". One in trouble gives its own words and how long it has been like that. Tapping the row opens its page, where the same line sits at the top.
