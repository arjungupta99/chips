A link asks before it lets anyone in

The second security review's SEC-42. Today an invite link, or a pairing link opened at the relay's page, lets whoever has it straight in. Your call: "Invites through the relay page wait for my Allow, and the Allow sheet shows a short code that must match the one on the joining device." The same goes for a pairing code: "Allow plus the matching code".

The code comes from the joining device's own key, so only that device can show it, and a link passed on to somebody else shows a different code. Below: who is asked, what they see, and what the joining phone shows while it waits.

Priya joins Japan trip from your invite

Arjun sends Priya an invite to Japan trip as a guest. She opens it on her iPhone, types her name and presses Join. Every phone of Arjun's that's open is asked; the first answer counts.

A computer pairs from Pair a computer

On his phone Arjun presses You → Pair a computer and opens the link on his laptop. The phone that made the code is asked, with B's sheet.

With it

  • Links last 30 minutes. Invite someone loses its Lasts choice and says the link works for 30 minutes. The limit is checked when a link is used too, so the 7-day invites out there now stop working.
  • Every link asks, the QR too, whenever a relay is set: today that's every link Chips hands out.
  • What stays. A dishonest relay page could still send Priya to another server dressed as yours, and she'd see that server's code. Only trusting the relay, or opening links outside its page, prevents that. It goes into SECURITY.md and ADR 0207.

To settle here

  • A or B for the sheet.
  • Six digits, read out as two threes, as drawn; or the letters a pairing code uses now (ABC-234).
  • Whether the sheet asks only the inviter's phones, as drawn, or every owner's.
